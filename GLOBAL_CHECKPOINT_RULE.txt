COMMAND CENTER CHECKPOINT + RECOVERY RULE — Whenever a meaningful verified project state changes (scope added/removed/resized, a roadmap phase or independently recoverable work unit completes/reopens, an approved/locked asset changes state, a blocker changes, a deployment/publication/account/integration/test milestone changes, or a Command Center KPI changes), persist/update the project’s canonical verified checkpoint before treating the work as synchronized. The checkpoint must preserve the complete current `state_json.scope` manifest and, when the project has a roadmap, the complete current `state_json.roadmap` manifest using stable IDs/weights plus protected/approved/locked work and the exact next resumable unit. Long-running work should checkpoint at meaningful recovery boundaries, especially after a phase/work unit, after meaningful QA, immediately before merge/publish/deploy, immediately after merge, and after live verification. On a freeze/interruption/new chat, recover the latest verified checkpoint, reconcile live state when available, preserve all verified completed/locked work, and resume from the first incomplete unit; never restart a phase merely because the prior chat ended. Progress percentages come only from defined verified roadmap/scope units and required quality gates, never from status wording, elapsed effort, or guesses. Verified fractional progress may display to one decimal place and must not be rounded upward to the next whole percent merely for presentation. If the newest verified checkpoint cannot support a current percentage, show N/A rather than carrying forward or fabricating one. User-approved or verified assets/packages remain locked unless explicitly reopened. Apply `ROADMAP_EXECUTION_STANDARD.md` to roadmap execution/resume/state/dependencies/idempotency/evidence. For book projects, apply both `BOOK_PROJECT_ROADMAP_STANDARD.md` and `BOOK_QA_GATES_STANDARD.md`, including humanization/reader-engagement, title-cover-interior alignment, coloring-book colorability, generation-protection, recipe-accuracy, image-match, and typography/layout gates. Apply `PROJECT_LINEAGE_OPPORTUNITY_STANDARD.md` when reconciling historical chats, scope drift, parked branches, or optional improvement/revenue opportunities. Optional opportunities never silently become active scope.
