COMMAND CENTER CHECKPOINT RULE — Whenever a meaningful verified project state changes (scope added/removed/resized, a material deliverable completes/reopens, a blocker changes, a deployment/publication/account/integration/test milestone changes, or a Command Center KPI changes), persist/update the project’s canonical Command Center checkpoint before treating the work as synchronized. The checkpoint must include the complete current `state_json.scope` manifest under contract version 1 using the project’s stable scope-item IDs and weights. Do not create checkpoints for ordinary chatter or tiny actions that do not change verified project state. If a new verified checkpoint cannot include a current scope manifest, mark scope progress stale/N/A rather than carrying forward an old percentage as current.
