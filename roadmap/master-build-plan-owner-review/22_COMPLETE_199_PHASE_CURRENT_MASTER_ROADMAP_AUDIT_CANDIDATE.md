## 8. Detailed new PIF phase scopes and gates

### PIF.1 — Shared intelligence contracts and ontology

**Scope:** Extend canonical IDs, shared ontology, claim/epistemic types, temporal fields, causal-vs-correlational separation, provenance, applicability scope, compatibility/version semantics, and privacy/data-class boundaries without duplicating C1/C3 canonical owners.

**Exit gate:** Contract tests reject ambiguous truth, incompatible ontology/version, missing provenance, invalid causal labeling, and unauthorized scope.

### PIF.2 — Capability / Method Portfolio

**Scope:** Extend the capability registry so one capability may retain multiple competing methods with method ID/version, applicable domains/tasks/conditions, contraindications, prerequisites, accuracy/quality/calibration, latency, resource/cost profile, privacy/security risk, reliability, benchmark and real-outcome evidence, fallbacks, rollback target, lifecycle, provenance, and revalidation state.

**Exit gate:** At least two valid competing methods can coexist, remain separately versioned, and be selected conditionally without changing core routing code or creating a universal default unsupported by evidence.

### PIF.3 — Specialist Model Registry

**Scope:** Register each subordinate specialist Brain/system with stable identity/version, Command Center relationship, domain/scope, supported companies/projects/work types, capabilities/methods, permissions, protected-action boundaries, data classes, provider/model/tool dependencies, calibration/evaluation history, resource profile, failure/degraded modes, fallbacks, learning eligibility, retirement/rollback state, provenance, and verification state.

**Exit gate:** A specialist cannot self-expand scope, inherit unauthorized data, bypass Command Center, or become a peer/top-level control plane.

### PIF.4 — Learning Packet + Promotion Governance

**Scope:** Add canonical Learning Packets containing source identity/evidence, originating capability/method/version, problem/task class, operating conditions, constraints, privacy-safe input summary, action, outcome, success/failure criteria, metrics, confidence/calibration, causal confidence/confounders, sensitivity, transferability hypothesis, negative knowledge, recovery lesson, freshness, validation state and provenance. Add promotion states GLOBAL / DOMAIN / BRAIN / TASK / CONDITION / EXPERIMENTAL / QUARANTINED / REJECTED / ALTERNATIVE.

**Exit gate:** Unvalidated, private, unsupported, stale, contradicted, or inapplicable learning cannot become global operational policy; alternatives remain separately versioned and reversible.

### PIF.5 — Epistemic / Contradiction / Uncertainty Layer

**Scope:** Extend knowledge/provenance with explicit states including OWNER_STATED, VERIFIED, CALCULATED, OBSERVED, INFERRED, GENERATED, HYPOTHESIS, ESTIMATE, STALE, CONFLICTING, SUPERSEDED, DISPROVEN, UNKNOWN and NOT_APPLICABLE; add contradiction records, uncertainty propagation, confidence decay, correlated-source awareness, calibration evidence, and decision thresholds.

**Exit gate:** Weak/conflicting evidence remains weak/conflicting; unsupported certainty is rejected; authority/evidence rules resolve or preserve contradictions without silent overwrite.

### PIF.6 — Layered Memory + Revalidation + Context Compiler

**Scope:** Extend C6 memory into canonical/shared/domain/specialist/company/project/task/episodic/semantic/procedural/negative/quarantined layers; add freshness/decay/expiry/event invalidation/revalidation; evolve Context Builder into a policy/evidence/method/applicability-aware Context Compiler that minimizes unrelated/private context.

**Exit gate:** Compiled context is task-relevant, fresh, authorized, privacy-minimized, version-aware, and unable to leak unrelated company/project data; stale memories trigger revalidation rather than silent use.

### PIF.7 — Evaluator / Outcome / Decision-Quality Foundation

**Scope:** Add evaluator registry and benchmark-class semantics for synthetic/replay/shadow/canary/production evidence. Store decision-time information, predictions/confidence, actual outcomes, controllable/external factors, confounders, causal confidence and resulting lessons.

**Exit gate:** Benchmark classes cannot be conflated; favorable luck cannot automatically promote a bad method; unfavorable luck cannot automatically invalidate a sound method; evaluator version/bias/source/evidence remain traceable.

### PIF.8 — Negative Knowledge + Transferability

**Scope:** Add evidence-backed negative knowledge for failures, traps, contraindications, invalid assumptions, unsafe combinations, provider limitations, recurring failure precursors and recovery lessons; add transferability records across specialists, companies, projects, task classes, domains, environments, provider/model versions, data regimes and resource constraints.

**Exit gate:** Failed/unsafe methods remain discoverable with scope and provenance; cross-system reuse requires compatibility/evidence, not similarity alone, and is revocable.

### PIF.9 — Trace + Dependency + Version Integration

**Scope:** Extend trace/dependency/version graph across context compilation, router, specialist, method, tool, evidence, verifier, state transition, outcome, learning packet, promotion, evaluator, ontology and learned procedure versions.

**Exit gate:** A decision and subsequent learning can be traced to exact versions/evidence; stale or incompatible dependents are detectable before use or promotion.

### PIF.10 — Self-Improvement / Recovery Invariants

**Scope:** Formalize proposal → evidence → applicability/risk analysis → offline evaluation/replay → simulation/shadow where applicable → baseline comparison → required authorization → canary/limited rollout → verification → promotion → monitoring → rollback → lesson capture. Extend recovery constraints so routing/calibration/promotions/evaluators/procedures/specialist state recover without reviving revoked access, invalidated learning or superseded policy.

**Exit gate:** No learned change silently mutates production or expands authority; rollback/recovery is deterministic and cannot resurrect forbidden scope or stale policy.
