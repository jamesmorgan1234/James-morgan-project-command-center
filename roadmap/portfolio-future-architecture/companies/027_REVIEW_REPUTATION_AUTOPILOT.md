# Company 027 — Review & Reputation Autopilot

**Company ID:** `company:future:027`  
**Primary project:** `project:company:future:027`  
**Roadmap version:** `COMPANY-027-v1.0.0`  
**Truth state:** PLANNED  
**Authorization:** roadmap/architecture only; no public review responses or customer messages.

## Business identity

Purpose: collect authorized/public review and customer-feedback signals, identify recurring issues, support evidence-grounded response workflows and measure reputation health across brands/locations.

Problem: organizations react inconsistently to reviews, miss systemic issues and lack cross-location/competitor context.

Value: centralized review intelligence, issue taxonomy, response assistance, recovery workflows and operational root-cause feedback.

## Product tree

Review Aggregator; Sentiment/Topic Analysis; Issue/Complaint Classification; Response Draft Assistant; Approved Response Workflow; Customer Recovery Tasking; Survey/NPS/CSAT Integration; Location/Brand Comparison; Competitor Review Comparison; Reputation Score; Recurring Root-Cause Analytics; Review Request/Feedback Routing only with consent; Alerting; Executive Reports; API/OEM; Vertical Packs.

## Feature/customer/vertical tree

Features: source/platform, review identity/reference, location/product/staff tags, language, sentiment/aspects, urgency, policy/legal flags, response status, approval, SLA, recovery outcome, recurring issue trend, authenticity/spam signal, accessibility/localization.

Customers: local/multi-location businesses, hospitality, restaurants, healthcare-adjacent practices, home services, ecommerce/brands, SaaS, franchises, agencies/reputation firms, enterprise CX.

Verticals: hospitality, food, retail/ecommerce, home services, professional services, automotive, property, SaaS/apps, education, healthcare admin. Industry-specific response/privacy constraints apply.

## Brain / architecture

Brain classifies sentiment/issues, summarizes recurring themes, drafts policy-compliant responses and identifies likely operational root causes. It must not fabricate facts, admit liability, expose customer data or post automatically without authorization. Architecture: review/source connectors, text classifier, taxonomy, LLM drafting grounded in account facts/policy, rules for approvals/privacy, analytics/time series.

## Agents

Review Intake Agent, Sentiment/Topic Agent, Urgency/Risk Agent, Response Draft Agent, Policy/Privacy Agent, Recovery Task Agent, Root-Cause Analyst, Location Benchmark Agent, Competitor Review Analyst, Survey Agent, Reputation Reporting Agent, Source Quality/Spam Agent.

## Deterministic services

Connectors; dedupe; language; taxonomy; sentiment/aspect scoring; response workflow; approval; task/SLA; alerts; survey ingestion; reputation metric engine; audit/export; communication protected-action gate.

## Workflow

Ingest review/feedback → verify source → classify sentiment/topic/risk → link location/product → determine response policy → draft cited/account-grounded response → approval → publish through authorized connector → create recovery task if needed → verify resolution → aggregate root-cause trend.

## Integrations / API / data

Review platforms/public listings, ecommerce/app stores, survey tools, CRM/support, location management, social authorized channels, BI, task systems. APIs for reviews/topics/reputation/tasks/response drafts/status.

Data moat: issue taxonomy, cross-location outcome history, response/recovery effectiveness and vertical benchmarks, with customer/reviewer data minimized.

## Monetization / distribution

Locations/brands/reviews/seats, premium competitor/survey/root-cause analytics, enterprise, agency multi-client, API/OEM, managed workflows. Distribution via local-business/CRM/support/location/ecommerce ecosystems and agencies.

## Security/privacy/legal

Public reviews may contain PII or allegations. Avoid exposing personal data, defamatory response generation or false admissions. Consent required for direct follow-up. Platform terms respected; review manipulation/fake reviews prohibited.

## Failure / edge cases

Sarcasm/multilingual errors, fake reviews, coordinated attack, legal complaint, health/privacy detail, duplicate cross-post, wrong location, platform API outage, owner facts unavailable. Use risk escalation, approved facts, human review and no fabricated response.

## Scale/overlap

Single location → franchise/multi-brand → enterprise CX reputation platform. Overlap #45 support, #89 support-QA; #027 remains external reputation/reviews.
