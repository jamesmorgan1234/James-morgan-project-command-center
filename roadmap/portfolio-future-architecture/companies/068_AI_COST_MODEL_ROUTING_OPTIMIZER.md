# Company 068 — AI Cost & Model Routing Optimizer

**Company ID:** `company:future:068`  
**Primary project:** `project:company:future:068`  
**Roadmap version:** `COMPANY-068-v1.0.0`  
**Truth state:** PLANNED  
**Authorization:** roadmap/architecture only; no paid-model activation, provider purchase, quota change or customer routing.

## Business identity
Purpose: choose the most suitable AI model/provider/configuration for each task under explicit quality, privacy, latency, reliability and cost constraints.

## Product tree
Model Catalog; Benchmark Registry; Task Classifier; Complexity Estimator; Routing Policy Engine; Cost/Latency/Quality Optimizer; Privacy/Data-Residency Router; Local-vs-Hosted Selector; Fallback/Outage Router; Ensemble/Consensus Planner; Prompt/Context Compression; Semantic Cache; Response Cache; Batch/Scheduled Inference; Quota/Budget Manager; Provider Health; Model Retirement/Migration; ROI Dashboard; Routing Simulator; API Gateway/SDK; Enterprise/Private Deployment; Vertical Evaluation Packs.

## Feature/customer/vertical tree
Features: model/provider/version, modalities, context length, tool/function support, regions, privacy class, benchmark scores, task families, price units, latency distributions, success/verification rates, quota, availability, cached equivalence, fallback graph, quality floors, cost ceilings, SLA, evidence and route version.
Customers: AI SaaS, agent platforms, enterprises, developers, model gateways, data/AI teams and software vendors.
Verticals: coding, document extraction, customer support, research, analytics, vision, audio/voice, regulated private workloads and high-throughput automation.

## Brain capability / architecture
Routing should primarily be deterministic constrained optimization over measured data; ML may predict quality/latency/cost; LLMs may classify task semantics but must not control budgets without policy. Architecture: provider/model registry, benchmark/eval store, task ontology, policy constraints, optimization engine, health/quota telemetry, cache, fallback DAG, privacy router, experiment service and cost ledger.

## Agent tree
Model Scout; Benchmark Agent; Task Classifier; Route Optimizer; Cost Analyst; Quality Evaluator; Latency Agent; Privacy Router; Provider Health Agent; Fallback Agent; Cache Optimizer; Migration/Retirement Agent.

## Deterministic services
Price normalization; token/media accounting; budget/quota checks; privacy eligibility; region eligibility; capability matching; stable ranking; fallback ordering; circuit breakers; cache keys; telemetry aggregation; model-version pinning; spend alerts.

## Workflow
Task request → classify task/sensitivity/SLA → enumerate eligible routes → remove privacy/capability/quota/budget violations → estimate cost/quality/latency → choose deterministic best route → execute through provider abstraction → verify outcome → record telemetry/cost → fallback only by ordered policy on failure → feed benchmark/route evaluation.

## Integrations / API / data
Model providers, local/self-hosted runtimes, AI gateways, eval frameworks, observability, billing/usage, data-residency policy and agent platforms. Data: model metadata, prices, benchmarks, route decisions, health, quotas, costs, quality outcomes; no unnecessary prompt retention.

## Monetization / distribution
Requests/tokens, managed spend, percentage of verified savings, gateway fee, enterprise/private, benchmark packs and API/SDK. Distribution via AI infrastructure/dev platforms and enterprise FinOps/AI governance channels.

## Security/privacy/legal
Provider selection must honor data classification/residency and customer contracts before cost. Secrets stay in provider vaults; route evidence must explain why a model was eligible. Avoid benchmark manipulation and undisclosed quality degradation.

## Failure / edge cases
Provider price change, benchmark drift, model alias changes, outage, quota depletion, token-estimation error, cached stale answer, local model unavailable, multimodal mismatch, safety/policy differences, quality metric gaming, latency spikes, silent provider model update.

## Scale / overlap
Single gateway → enterprise AI FinOps → global model control plane. Overlap Command Center P6.2, #3 AI QC, #95 ROI. #068 commercializes routing optimization; Command Center needs an internal version now.

## Classification
**DESIGN NOW:** provider/model abstraction, immutable version identity, route policy, cost/quality/latency/privacy telemetry, deterministic fallback, free-first preference.  
**BUILD NOW:** Command Center already needs these in P6.2; portfolio reverse-map confirms this is foundational.  
**BUILD BEFORE FIRST COMPANY:** external tenant gateway, metering and customer policy.  
**COMPANY-SPECIFIC LATER:** commercial benchmarks/providers/pricing.  
**SCALE-ONLY:** global routing fabric and sophisticated multi-provider arbitrage.
