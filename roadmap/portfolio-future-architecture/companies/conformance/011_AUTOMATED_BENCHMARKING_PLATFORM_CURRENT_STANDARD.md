## Company-specific augmentation

The source already defines cross-functional peer benchmarks, metric ontology and translation, cohort eligibility, minimum cohort sizes, anonymization, confidence/statistics, normalized distributions, proprietary indices, private peer groups, embedded/API delivery, vertical packs, Brain/agent/service trees, monetization, security and scale. This supplement closes current-standard branches that are only implicit in v1.0.0.

- **Acquisition / lifecycle:** acquisition can use methodology content, sample packs, associations, analysts, embedded integrations and controlled trials. Customer lifecycle is metric contract → authorized source mapping → quality/comparability validation → cohort/privacy eligibility → shadow computation → reviewed publish → drift monitoring → renewal/expansion → export/offboard. No outreach or partnership execution is authorized by this roadmap.
- **Support / success / administration:** handle metric-definition disputes, unit/currency/accounting-period mismatches, source freshness, cohort eligibility, quality failures, percentile/index interpretation and privacy-method explanations. Operate versioned metric/cohort/source/index registries, contribution consent, customer roles, billing/metering, retention, support and offboarding.
- **Legal / privacy / abuse:** data contribution rights, confidentiality, licensed/public source terms, sensitive HR/financial measures, regional restrictions and reidentification controls remain separate governed requirements. Detect cohort probing, benchmark gaming, synthetic skew submissions, unauthorized redistribution and attempts to infer another participant’s values.
- **Observability / incident response:** measure sample size, entropy/reidentification risk signals, comparability, missingness, outlier pressure, source freshness, cohort/index stability, disclosure-control denials, query/report latency and cost. On incident freeze affected cohorts/indices, quarantine source/mapping, mark outputs stale/unknown, recompute from last valid version, retract/correct results and preserve correction evidence.
- **Testing / Brain evaluation:** verify semantic mappings, unit/currency normalization, percentile/confidence correctness, cohort eligibility, minimum-size/privacy rules, selection/survivorship effects, index reproducibility, reidentification probes and Brain grounding. The Brain must never invent peer data or expose identifiable competitor values.
- **Deployment / performance / cost:** shadow candidate metric/cohort/index/privacy changes, canary by cohort/version, preserve deterministic historical recomputation and rollback. Track ingest/query/recompute latency, storage/warehouse/API/report cost, privacy-computation overhead and cost per metric/query/customer.
- **Financial truth:** future MRR/ARR, gross/contribution margin, source/data cost, compute cost, support burden and retention/expansion are real only when externally verified; sample benchmark use is not revenue.
- **Internationalization / accessibility / interfaces:** locale, currency, unit and accounting-period normalization plus region/privacy packs; accessible dashboards/reports; mobile alerts/briefs; optional voice; multimodal evidence only with provenance and comparability controls.
- **Training / experimentation / improvement:** publish metric dictionaries, comparability/privacy methodology, admin/analyst training and API guides. New cohort rules, mappings, outlier policies and index formulas run against historical snapshots before activation. Verified corrections become regression cases.
- **Safe mode / portability:** disable by source/metric/cohort/index/API/customer, pause contributions, freeze publishing, serve read-only validated history and roll back computation versions. Export contributed data where permitted, mappings, benchmark history, reports, configs and consent records; revoke integrations and apply retention/deletion rules.
- **Reuse / dependency / blast radius / compatibility:** metric registry, semantic mapping, privacy aggregation, statistics, lineage, quality, reporting, API and observability are reuse candidates only after proof. Shared ontology/cohort/privacy/index errors can distort many customers, so isolate by metric/cohort/version and preserve forkability. Every result remains attributable to metric ontology, cohort criteria, privacy policy, source mapping, outlier rules, index formula and API/report version.
